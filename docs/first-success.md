# Your first successful collaboration

Start in **Projects**. Create/open a project and follow its **First success guide**, or explicitly choose **Try an isolated sample**. The guide is useful without an agent and does not start execution when opened.

1. Describe one concrete goal and acceptance criteria in a project/requirement.
2. Prepare a plan draft. Review its tasks and dependencies, validate the saved revision and explicitly apply it. New requirements remain draft. Return to the guide to resume the saved draft or inspect the applied records.
3. Inspect the requirement and explicitly approve it when its scope is ready. Draft requirements are not executable.
4. Optionally connect an agent using existing scoped credentials, repository readiness and Daemons executor diagnostics. The API capability panel reports actual observations; unavailable checks remain unknown. Repository or executor registration alone does not prove that execution is permitted. Skip this step for manual planning or the written sample.
5. Produce an outcome through the existing task actions. The sample asks for a one-sentence task comment and a completed task. Copy that comment's ID for the next step.
6. Register the comment output in the requirement workflow. Inspect it, complete delivery with a reason, then record acceptance. A completed task alone is not a reviewed outcome.

The guide follows the most recently updated non-cancelled requirement in the selected project and uses current task, output and workflow records. Available output must match current plan/workflow revisions; stale evidence does not establish completion. Refreshing or returning recomputes progress. Only hide/optional-agent preferences are saved in actor/project-scoped browser storage; credentials and business completion are never saved there. **Hide guide** can be reversed with **Show first-success guide**.

Sample content is isolated in a project named **[Sample] First successful collaboration**. Creating the project and staging its plan are explicit actions. The sample plan stays unapproved until applied and approved through the existing screens. **Archive this sample project** cleans up the active workspace while retaining all sample records; restore through project settings if needed. Other projects are unaffected. A staged plan can also be discarded before application.

For existing projects, the guide reflects existing work rather than resetting it. Viewers receive read-only guidance; missing access or failed requests show unknown state. For production acceptance, validate your own repository, executor credentials and a real delivered result separately. Local operator fixtures do not demonstrate autonomous agent execution.
