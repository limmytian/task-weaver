# 记忆生命周期与跨会话衔接

先用 `tw_memories_search` 检索摘要，再用 `tw_memories_get` 按需读取正文。
检索采用关键词及作用域、创建者相关性加权，不依赖 embedding 服务；默认排除过期内容，
读取不会自动续期。最多返回 20 条摘要且总量不超过 16 KiB；`hasMore` 表示需要缩小查询，
不承诺尚未实现的分页。

`tw_memories_record` 必须显式指定 `confirmed: true` 和 UUID `idempotencyKey`。
个人空间的所有者来自凭据。保存会记录创建者、来源实体、来源说明、有效期及版本。
来源说明是可审阅的数据，不代表指令可信，也不构成执行授权。

`tw_memories_preview` 从有权限的任务、需求或 Markdown 文档生成有界摘录草稿，
不写入记忆，也不调用模型。它不是自动语义总结；附件需要单独提取可读文本。
审阅或编辑后才显式保存。保存时来源更新时间必须仍与预览一致，否则重新预览。
已保存的来源记忆会通过 `sourceFreshness` 提示来源变化；重新审阅后，可以带当前
`expectedVersion` 和新来源说明显式修订。工具输出不会被自动提升为长期指令。

保存响应不确定时，用相同内容和同一个 key 重试，返回当前已保存条目，不覆盖后续修订。
同一个 key 改用其他内容会冲突。凭据撤销、权限或作用域变化后，重试仍会重新鉴权。
忘记后保留只含请求哈希的去重记录，旧请求不会复活正文；确实要重新保存时使用新 key。

修订和忘记都需要当前 `expectedVersion`，忘记还需要显式确认。
普通读取隐藏过期条目；显式 `includeExpired: true` 可在有权限时检查，并明确标记为过期。
正文、存储元数据和完整工具 schema 不会注入搜索摘要或 bootstrap。

REST 保存可传 `idempotencyKey`，PATCH 可传 `expectedVersion`，DELETE 可传
`?expectedVersion=N`。旧调用方式继续兼容；MCP 则强制使用这些保护。
CLI 示例见[英文规范](memories.md)。

启动新代码前需应用增量迁移 `0074_memory_lifecycle`。遗忘会删除记忆行及其数据库检索项，
没有独立的记忆向量索引遗留；这不承诺删除运营备份或外部客户端已经保留的对话副本。
去重记录应在旧请求仍可能重试期间保留。英文版本为规范基准。
