# Task Weaver 0.3.12

私有候选版本已经 owner 验收，现准备正式发布。[English](0.3.12.md)。

## 一个入口使用托管能力

通过一个 TW MCP HTTP 连接或 `tw mcp serve`，按权限发现并使用指令、技能包、记忆、
外部工具。初始上下文只加载受限摘要，正文、依赖与工具 schema 按需读取。
统一资源身份、作用域和不可变执行清单本身不会授予访问权。

记忆增加来源预览、provenance、新鲜度检查、显式审核写入、版本并发控制、过期和幂等
回执，遗忘后的旧请求不能复活内容。检索采用有界关键词与作用域匹配，本版本没有新增
向量记忆检索，也不会自动将对话提升为永久指令。

技能包固定精确版本与原始字节，检查依赖可见性、冲突和循环；符合条件的可执行包可在
管理员批准的隔离运行环境中执行。缺少镜像或解释器会明确提示，不会自动安装依赖或拉镜像。

统一 MCP 代理支持按权限发现、按需读取 schema、哈希确认调用、就绪诊断、限流、截止
时间、连接冷却与故障隔离。批准的托管 stdio 服务使用离线容器和限定 Secret 引用。
本机文件、设备仍需显式本地桥接；断线后的已派发调用不会自动重放。

## 协作

协作能力补充有界依赖和 claim 邻域、文档历史、交付引用，以及 daemon、日程和仓库
运行上下文，并明确截断和新鲜度。通用说明不再绑定滚动版本号，运行时使用共享元数据，
历史发布、升级和依赖证据仍保留精确版本。

CLI 对 DNS、TLS、超时、取消、连接和无效响应提供安全错误分类。写请求丢失响应时提示
可能已经提交，不自动重试，也不绕过 TLS 校验。

MCP TypeScript SDK 直接依赖从 1.31.0 升至 1.32.1，包含 [GHSA-22jm-h49p-29qw](https://github.com/modelcontextprotocol/typescript-sdk/security/advisories/GHSA-22jm-h49p-29qw)
和 [GHSA-46jr-4wx8-v453](https://github.com/modelcontextprotocol/typescript-sdk/security/advisories/GHSA-46jr-4wx8-v453)
的修复。入站 HTTP 请求体仍限制为 1 MiB，Task Weaver 未使用实验性 task store。

## 升级与验收

从 0.3.11 升级需执行 `0074_memory_lifecycle`、`0075_ti_sandbox_ownership`、
`0076_webhook_outbox` 和 `0077_verified_inbound_events`，再启动新应用。
协调备份数据库、原始包对象与配置/Secret 设施，
保留记忆回执、不可变包版本及生命周期回执。仅切换镜像不代表旧代码
能够理解新记录；需演练协调恢复，并处理备份后的写入与重试状态。

托管运行环境默认关闭，需要批准的配置和预置镜像。参见[使用指南](../hosted-capabilities.zh-CN.md)
及[运维指南](../hosted-capability-operations.md)。

实际官方 MCP SDK 的 HTTP 和真实 CLI stdio 客户端已完成单 TW 入口的发现、记忆读取、
托管工具调用、隔离技能执行及跨传输交接；stdio 使用空 home/config 与无本地工具 PATH。
这些测试不代表认证某个厂商桌面、原生 skill 加载或 OAuth-only 界面。


## Ti 执行与沙箱归属

聊天、手动任务和 schedule 生成的任务共用有界模型/工具循环，以及平台技能、记忆、
HTTP MCP 与 Partners MCP 适配器。聊天保留确认流程，任务保留委托权限、执行租约和
attempt 校验。共享 worker 执行真实模型调用，不再仅打印提示词；需显式配置限定权限的
Agent 凭据以及 Partners 租户和项目。

沙箱归属持久化绑定 TW 用户、会话或 run/attempt，模型只使用逻辑操作句柄，资源 ID 由
服务端确定。取消、清理重试、配额与清理债务检查仅处理 TW 明确拥有的资源，TTL 仅作
兜底。中断的模型派发恢复到人工复核，不重放结果不确定的外部操作。由于提供方不支持
逐命令关闭网络，shell 执行要求任务策略显式允许网络。

执行循环限制轮数、工具调用、上下文、累计 token 和租约时长；MCP 参数在派发前校验，
保留不确定调用错误并记录实际用量。模型可用 JSON 编码传入动态 MCP 参数，已有审批的
对象参数保持兼容。

## 可靠外部事件

业务写入以事务方式持久化出站事件。投递使用稳定事件 ID、租约、有限重试、带时间戳的
HMAC 签名和历史记录。重放在当前授权下创建新投递；配置变化保留有权读取的历史元数据
及尝试记录，但不恢复旧代次的发送或重放资格。接收端应校验签名并去重。

入站来源先验证原始请求签名，再解析并持久化去重回执，在固定项目和需求内执行有限的
声明式动作：任务、评论、允许的字段更新、证据及既有 schedule 触发。撤销凭据或改变
来源代次会阻止旧工作继续执行。不恢复插件生态，不新建 MCP 轮询系统。

真实模型验收覆盖聊天、手动任务、schedule、平台技能/记忆、HTTP MCP 及远端沙箱文件与
命令操作；另验证了取消、应用重启后不重放、权限撤销、归属隔离和删除。部署环境完成
签名入站经 schedule 和真实模型到出站的链路、503 重试及重放。丢失响应、事务回滚和
重试恢复由独立的数据库故障注入测试验证，不与远端真实验收混为一谈。
