# Task Weaver 0.3.13

[简体中文](0.3.13.zh-CN.md).

## Live planning changes

Web, CLI, REST and MCP planning changes use shared core impact rules for task and
requirement descriptions, acceptance, dependencies, slices, assignment, repository
scope and execution inputs. Changes that invalidate execution immediately revoke
old authority. Persistent controls distinguish notification, stopping, stopped and
resumed states, with SSE replay and heartbeat/polling fallback. Unrelated tasks
and the daemon itself remain available.

## Bounded execution recovery

Healthy nodes retain their workspace and renew leases through stopping, evaluation
and fresh-run continuation. Waiting for dependencies releases worker capacity.
Node affinity is a preference; configured grace periods and retry budgets permit
safe tasks to restart on another node using durable inputs and remote code.
Local progress can be lost and computation repeated. Non-repeatable external
operations and irreplaceable local inputs require explicit recovery handling.
Returning nodes reconcile authority and retain stale work for inspection rather
than overwriting newer execution. Already-dispatched Git or external operations
can have uncertain results; physical exactly-once execution is not guaranteed.

## Git synchronization and delivery

Agents must fetch and reconcile the latest target branch before work and again
before delivery. The daemon provides authenticated, authority-checked Git access;
merge/rebase, conflict resolution and validation remain agent responsibilities.
A fetched branch does not automatically update an existing worktree. Invalidated
work requires provenance inspection before reuse. Synchronization failures block
execution; no force push or handoff-commit protocol is introduced. Automatic
daemon commits now include DCO signoff. Linux execution identity and process-group
inspection use procfs so minimal container hosts do not depend on GNU ps.

## Release dependency maintenance

The locked release dependencies update Next.js to 16.4.3, DOMPurify to 3.4.17,
body-parser to 2.4.0, @graphql-tools/utils to 12.0.2 and Zod to
4.6.6 to clear the release-blocking security advisories. Shared schemas now use Zod 4, with explicit record keys, sparse enum records,
creation prefaults, omitted patch-field preservation and native input JSON Schema
conversion. Zod 3 is no longer present in the locked dependency graph. Consumers that inspect
or compose the exported Zod schemas must use Zod 4-compatible APIs; validation
issue messages and issue codes follow Zod 4. Existing JSON resource shapes remain
the transport contract.

## Upgrade and verification

Apply database migration `0078_execution_controls` before starting this version.
Back up PostgreSQL and local package/workspace data with configuration and Secrets.
Coordinate database/data restoration when rolling back; an old image alone is
not a verified rollback. Review [execution recovery operations](../live-planning-recovery.md)
and the [upgrade guide](../ce-upgrades.md).

Acceptance includes database and daemon fault tests, two physical nodes with an
actual network partition and returning stale node, and a real Codex code task
whose plan and remote branch changed during execution. The real agent inspected
preserved provenance, resolved a Git conflict, passed tests and delivered a signed
commit through the daemon. That model-driven Git acceptance used a disposable
local bare remote; it does not certify every external forge or model provider.
