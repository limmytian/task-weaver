# Task Weaver 0.3.15

[简体中文](0.3.15.zh-CN.md).

## Human-reviewed plan staging

AI-proposed plans are staged as persistent server-side drafts before anything
is applied. Drafts keep revisions and validated live-graph fingerprints,
survive reloads, and apply atomically with permissions, versions, the merged
dependency graph and execution leases re-checked in the same transaction.
Concurrent edits and double submissions produce one plan with idempotent
receipts, and a failed application leaves no partial plan behind. Staged
entries and dependency edits are validated against the merged graph, mixed
new and existing edges are supported, and duplicate or cyclic staged
dependencies are rejected with actionable diagnostics. Plan slice lanes show
task assignments, staged assignments are editable, and the plan editor stays
usable on narrow screens. New requirements remain `draft`; staging never
schedules work, and a requirement entry point connects Assistant handoff to
explicit apply confirmation.

## Verified evidence review

Deliverables can now be reviewed against their exact source. Workflow outputs
bind to signing nodes and immutable file versions; reads use an authenticated,
bounded node-read protocol with expiry, replay protection, cancellation and
per-node concurrency limits. Paths come from the registered output inventory
only, and reads are confined against traversal, symlink and replacement races
with full-file fingerprint verification and recorded read outcomes.

Bounded previews cover text and Markdown, CSV/TSV tables, images, supported
audio/video and PDF, with JavaScript and TypeScript diffs highlighted.
Sampling and truncation are labeled explicitly, and downloading the original
bytes is a separate opt-in authenticated action; active formats such as
HTML/SVG remain download-only. Git comparisons pin base and head to immutable
commits so trees and pagination do not move with the branch. Verified evidence
promotes to regular attachments bound to immutable file versions; repeated
promotion does not duplicate attachments and failed promotions clean up.
Promoted attachments stay readable while the execution node is offline, and
permission revocation or fingerprint corruption is never bypassed through
fallback. Evidence producers report availability, trusted forge responses stay
bounded while streaming, and daemon execution verifies evidence reads.

## Security and transport hardening

The new evidence and worker-console Web entry points authenticate before
resource validation and are covered by the disposable-PostgreSQL transport
suite. Authenticated evidence responses are not cacheable, unsupported text
encodings are rejected, artifact roots resist traversal, and interrupted or
rejected evidence promotions cannot leave verified previews behind.

## Upgrade and verification

Migrations `0079_plan_drafts`, `0080_evidence_node_binding`,
`0081_evidence_attachment_binding`, `0082_evidence_promotion` and
`0083_evidence_git_comparisons` only add tables and columns; no existing data
is rewritten. Back up PostgreSQL and skill/attachment data before upgrading as
described in the upgrade guide.
