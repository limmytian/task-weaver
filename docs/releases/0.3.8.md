# Task Weaver 0.3.8

Changes from 0.3.7. Package and runtime versions are promoted together to `0.3.8`.

## Configurable requirement workflows

Requirements support configurable delivery, acceptance and integration stages,
with automatic, manual or skipped execution and stage-specific agent instructions.
Web, REST, CLI, batch creation and plan application resolve an explicit requirement
configuration, then the project default, then the basic workflow. Effective
configuration is saved at creation; later project changes do not rewrite it.

New requirements default to automatic delivery without a required output and
skipped acceptance and integration. All tasks must finish or be cancelled before
delivery completes. Existing requirements retain their legacy behavior until
explicitly migrated before execution. Pull requests and Git worktrees are optional
capabilities rather than universal delivery requirements.

Outputs can be comments, attachments, URLs, local files, Git branches or pull
requests. Local bytes remain on the producing machine; registered dependencies
constrain scheduling to a compatible node and unavailable or changed files block
consumption. Artifact and clean-worktree cleanup is explicit and respects retention
and active consumers. See [requirement workflows](../workflows.md).

## Human pull request delivery reconciliation

Authorized humans can register or synchronize an existing GitHub or Gitea pull
request through Web, CLI or REST. The server reads trusted forge evidence and
checks repository, branch and commit identity. Revision checks, active-lane guards,
idempotent retries and audit records protect concurrent changes. Synchronization
preserves review decisions and does not automatically approve or complete workflow
stages. Completion errors now explain outstanding repository or workflow conditions.
See [manual PR reconciliation](../manual-pr-reconciliation.md).

## Upgrade and recovery

Back up PostgreSQL, skill storage, attachment storage and the credential encryption
key ring before upgrading. Migration `0070` adds requirement/project workflow
configuration, output and dependency tracking, node identity and stage execution
delegations. Preserve daemon node identity and durable artifact directories for
local-output consumers. Keep artifact storage outside disposable worktrees.

Public GitHub synchronization can read anonymously. Private GitHub or Gitea
connections require an operator-managed `TW_FORGE_CONNECTIONS_FILE` with exact
repository ID and coordinate allowlists and optional token-file references; never
store forge credentials in requirement instructions. Preserve existing Secrets.
For recovery, restore matching database and persistent-storage snapshots with
recorded previous image digests. Do not run older application code against the
upgraded schema without the matching restore.
