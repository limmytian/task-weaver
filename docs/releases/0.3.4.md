# Task Weaver 0.3.4 — prepared source

Changes from 0.3.3. These notes describe the `0.3.4` development branch; release
artifacts, version promotion and deployment remain separate steps.
[简体中文](0.3.4.zh-CN.md).

## Account and credential usability

- Sign in uses instance session defaults. Invitation and recovery have an explicit
  secondary entry; first-instance setup appears only when readiness is verified.
- The account menu groups account settings and sign out. Sensitive actions request
  identity confirmation in context; cancelling leaves the action unapplied.
- Managed Agents default to active identities. Disabled identities have their own
  searchable, paginated view and can be hidden by soft deletion. Retirement is
  irreversible. Duplicate names retain distinct IDs and never inherit authority.
- Agent details show project access and separate explicit execution permissions
  from role permissions, with guidance from identity creation to scoped Key setup.
- Ordinary Key details show named scopes, immutable subject, status, expiry and
  editable grants, with before/after summaries and stale-write handling. Saved
  grant changes invalidate derived credentials and execution delegations; later
  expansion never revives them. Raw secrets remain visible only at issuance.
- Permission selection supports bounded search/pagination, explicit cross-page
  selections, group/page/filtered/all-eligible selection and partial-selection
  states. The existing limit is 100 explicit scopes per Key. Selecting current
  projects never grants future projects.
- Ti entry points use the Chat Sparkles icon; Agent Usage uses an analytics icon.

## Executor availability and recovery

Daemon tool profiles report resource interruptions separately from Agent identity
and run token totals. Confirmed quota/rate-limit blocks pause acquisition and
execution for the affected profile; authentication and billing require action.
Fenced recovery preserves saved work, terminal tasks and completed deliveries.
Resource interruptions do not consume task, review or delivery retry budgets, and
an interrupted AI review does not generate code findings or approve the work.

The Daemons page highlights blocked tools, quota windows, reset times and recovery
actions, with technical details and recovery history available on demand. Refresh
queues a check for the online daemon and preserves existing blocks. Authorized
retry records a reason and leaves availability unverified until a check or run.

Codex supports bounded read-only quota inspection. Other tools have no verified
automatic quota-query integration in this version. Antigravity users can view
quota through interactive `/usage` or `/quota`; this is not yet connected to Task
Weaver. Unsupported, missing and stale counters remain unknown. Automatic
cross-tool fallback is disabled by default and requires an explicit finite project
policy, fresh subscription evidence and compatible task constraints; paid API
fallback is denied. See [executor availability](../executor-availability.md).

## Compatibility and upgrade

The migration journal adds three entries after 0.3.3:

- `0059_agent_retirement`: irreversible identity retirement metadata.
- `0060_key_grant_version`: optimistic concurrency for Key grant changes.
- `0061_executor_availability`: durable tool observations/history and nullable
  project fallback policy.

Apply the complete migration journal before using the new source against an
existing database. Back up and rehearse upgrades using the
[upgrade guide](../ce-upgrades.md). Existing published tags and artifacts are not
modified. Older daemons do not report availability; upgrade participating workers
to enforce resource gates. Subject-bound authentication, project permissions,
credential ceilings, recent identity confirmation and lease fences remain in force.

Package/runtime versions remain at the released baseline until version promotion
is explicitly authorized. No new published package, image, tag or deployment is
implied by these source notes.
