# Task Weaver 0.3.11

## MCP 规划与上下文协作

新增 14 个工具，覆盖技能检索、技能包安全文本读取、执行切片、计划原子提交和任务／需求
聚合上下文。总计 43 个工具，其中只读模式可见 23 个；HTTP 与 stdio 共用契约和授权执行器。

计划支持无写入预览和持久化 UUID 去重 key，按凭据与项目隔离：相同计划重试返回已有
结果，不同内容冲突。拒绝嵌套越权字段和跨项目引用。切片更新检查精确 `updatedAt` 并遵守
需求租约。聚合读取明确标记截断、续读方式和非快照一致性，不递归展开文档或读取任意路径。

## 升级

先备份数据库与对象存储，执行 `0071_mcp_plan_receipts` 迁移，再启动新 API；本地 `tw`
同步升级后使用新增 stdio 工具。活动凭据的去重记录须保留；轮换密钥会改变去重范围。

工具名称、权限、大小限制和重试语义见 [MCP 使用指南](../mcp-server.zh-CN.md)。

## 计划中的 MCP 授权增强

0.3.11 后续计划让 MCP 工具目录实时反映当前凭据的授权。发现阶段按工具权限、服务器
状态和只读策略过滤；调用阶段必须重新校验，避免缓存目录在权限撤销后继续调用。
可见工具应标明来源服务器、所需权限和可用状态，不向调用方泄露其无权使用的工具。

MCP 调用应生成受范围约束的审计记录，包含操作者/凭据、项目或全局范围、服务器与工具、
结果、稳定错误类别和耗时。不得记录参数、结果正文、密钥或上游响应正文。为敏感写操作
增加可配置策略，按需要求显式审批；审批执行时重新验证身份、授权和目标资源。

当前授权模型已区分全局授权和实例授权：全局 `resource.read` 覆盖全局资源；项目搜索和
项目数据仍只限调用方有权读取的项目。计划增加独立的全局 `project.discover`，用于受限的
项目目录搜索，只返回项目元数据，不授予项目内容读取权。创建项目仍使用实例范围的
`project.create`，不会因此获得所有项目的访问权。计划规定：通过 MCP/API Key 创建项目时，仅给执行创建操作的
人类主体绑定凭据，原子授予新项目的 `resource.read` 和 `resource.write`。该窄范围派生授权
须有审计记录，仍受实时成员关系约束，且不包含项目管理、执行、MCP 管理权限，也不覆盖
未来创建的项目；项目创建失败时不得留下授权。

验收覆盖 HTTP 与 stdio 的发现/调用一致性、授权撤销/服务器停用/只读切换的即时生效、
搜索及审计无跨项目或全局数据泄漏，以及项目创建、授权派生和事务回滚。以上为计划项，
不是当前 0.3.11 候选版本已实现的行为。
