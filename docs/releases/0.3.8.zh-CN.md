# Task Weaver 0.3.8

本版本基于 0.3.7，包版本与运行时版本统一升级至 `0.3.8`。

## 可配置需求工作流

支持配置交付、验收、整合阶段，各阶段可自动执行、人工处理或跳过，
并可填写独立的 agent 指令。Web、REST、CLI、批量创建和 plan 使用相同
优先级：需求显式配置 → 项目默认配置 → basic。创建时保存有效配置，
修改项目默认值不会改写已有需求。

新需求默认自动交付，无需产物，跳过验收和整合；任务全部完成或取消后
才能完成交付。历史需求保留旧行为，可在执行前显式迁移。
PR 和 Git worktree 按需使用，不再是所有任务的交付前提。

产物支持评论、附件、URL、本地文件、Git 分支或 PR。本地文件不会自动上传；
声明依赖后，调度受节点约束，文件缺失或内容变化会阻止消费。
产物和干净 worktree 的清理需显式执行，并检查保留期及消费者状态。
详见[需求工作流](../workflows.zh-CN.md)。

## 人工 PR 交付同步

有权限的人类用户可通过 Web、CLI、REST 登记或同步已有 GitHub / Gitea PR。
服务端读取可信平台证据，校验仓库、分支和提交身份，并通过版本检查、
执行占用保护、幂等重试和审计记录保护并发操作。同步保留原有验收决策，
不会自动批准或完成工作流。需求完成受阻时会说明尚未满足的交付或阶段条件。
详见[人工 PR 同步](../manual-pr-reconciliation.zh-CN.md)。

## 升级与恢复

升级前备份 PostgreSQL、技能存储、附件存储及凭据加密密钥环。
迁移 `0070` 增加工作流配置、产物与依赖记录、节点身份和阶段执行委托。
本地产物消费者需要保留 daemon 节点身份和持久产物目录；产物目录应放在
临时 worktree 之外。

公开 GitHub PR 可匿名读取。私有 GitHub / Gitea 连接需由操作者配置
`TW_FORGE_CONNECTIONS_FILE`，精确限制仓库 ID 和仓库路径，凭据使用令牌文件引用，
不要写入需求指令。保留现有 Secret。恢复时应同时恢复匹配的数据库、持久存储
快照和旧镜像摘要，不要直接以旧应用运行升级后的数据库。
