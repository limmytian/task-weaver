# Task Weaver 0.3.11

## MCP planning and contextual collaboration

The inbound MCP Server adds 14 tools for skill discovery, safe skill-package
text reads, execution-slice planning, atomic plan submission and bounded task
or requirement context. The maximum catalog contains 44 tools, including 24 read-only tools;
each credential sees its current authorized subset. HTTP and stdio share schemas and the authorized executor.

Plans support mutation-free previews and persistent credential/project-scoped
UUID idempotency keys. Identical retries return the committed receipt;
conflicting payloads fail. Nested privileged fields and cross-project references
are rejected. Slice updates check the exact current updatedAt and respect
requirement leases. Context reads expose truncation, continuation and honest
read-committed freshness, without recursive document bodies or arbitrary paths.

## Upgrade

Back up database and object storage, then apply migration
`0071_mcp_plan_receipts`, `0072_api_key_project_creations` and
`0073_mcp_security` before starting the new API. Upgrade local `tw` clients
for the additional stdio tools. Preserve receipts for active credentials;
rotating keys changes the retry namespace. The additive table can remain during
a temporary 0.3.10 rollback. Existing 29 collaboration tools remain compatible.

See [MCP setup and examples](../mcp-server.md#planning-and-context-tools-0311)
for tool names, scope requirements, input/result limits and retry semantics.

## MCP authorization and project access

Adds `global.project.discover` for bounded directory metadata and atomic,
Key-specific read/write grants when a human-bound Key creates a project.
Outbound discovery requires a live invoke path, connected server and tool scope;
inbound HTTP/stdio discovery follows current grants and read-only policy.
Invocations reauthorize every target. Adds scope-isolated metadata-only audits,
trusted read-only/project-argument declarations and configurable one-time
approvals for sensitive operations. Existing unconfigured calls remain allowed
by policy while retaining their normal permission checks.

Upgrade API and CLI together. Older stdio clients may display a static catalog;
server-side call checks still apply. New clients require the catalog endpoint.
A rollback can retain all additive tables/columns, but older APIs do not enforce
these new policies. Disable MCP access while rolling back if these controls are
required, and restore the recorded application/configuration pair. For a full
data rollback, stop writes and restore the complete pre-upgrade backup; removing
provenance or policy rows independently can change credential behavior.
