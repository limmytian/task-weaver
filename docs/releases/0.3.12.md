# Task Weaver 0.3.12

Release prepared after owner acceptance of the private candidate.
[简体中文](0.3.12.zh-CN.md).

## Hosted capabilities with a minimal client

A single Task Weaver MCP HTTP connection or `tw mcp serve` can discover and use
scoped instructions, packages, memories and external tools.
Bootstrap and summary budgets keep full instruction bodies and tool schemas out
of initial context; details load on demand. Resource identities, scope and immutable
execution manifests are shared across interfaces and do not confer authority.

Memories gain source-linked previews, provenance/freshness checks, explicit reviewed
writes, revision guards, expiry and receipt-backed retry/forget protection. Retrieval
uses bounded keyword/scope matching; this release does not add vector memory search
or automatic promotion of conversations into instructions.

Skill graphs pin exact versions and original bytes, reject inaccessible/conflicting
or cyclic dependencies, and materialize eligible executable packages in approved
isolated runtimes. Discovery reports missing images/interpreters with remediation.
No automatic dependency installation or image pulling is introduced.

The external MCP facade provides scoped discovery, on-demand schema pins, reviewed
calls, readiness, admission/deadline limits, connection cooldown and failure isolation.
Approved hosted stdio profiles run offline with scoped Secret references. Local
files/devices still require an explicit local bridge. Dispatched calls are not
silently replayed after connection loss.

## Collaboration

Collaboration tools add bounded dependency/claim neighborhoods, document history and
delivery references, daemon/schedule/repository operational context, truncation and
honest freshness. General instructions no longer bind themselves to a rolling release.
Runtime version identity comes from shared metadata; historical pins are retained.

CLI transport failures now have safe DNS/TLS/timeout/cancellation/connection/invalid
response categories. A lost mutation response warns that the operation may have
committed; no automatic retry or TLS bypass is introduced.

The direct MCP TypeScript SDK dependencies are updated from 1.31.0 to 1.32.1 to
include fixes for [GHSA-22jm-h49p-29qw](https://github.com/modelcontextprotocol/typescript-sdk/security/advisories/GHSA-22jm-h49p-29qw)
and [GHSA-46jr-4wx8-v453](https://github.com/modelcontextprotocol/typescript-sdk/security/advisories/GHSA-46jr-4wx8-v453).
The inbound HTTP request body remains capped at 1 MiB, and Task Weaver does not use
the experimental task store.

## Acceptance boundaries

Actual official MCP SDK HTTP and CLI stdio clients complete one-TW guidance/dependency
discovery, memory recall, hosted tool invocation, isolated skill execution and
cross-transport handoff. The stdio client uses an empty home/config directory and no
local tool PATH. Vendor desktop/native skill loading and OAuth-only UIs are not
certified by these transport tests.

## Shared Ti execution and owned sandboxes

Chat, manual tasks and schedule-created tasks share a bounded model/tool loop and
platform skills, memories, HTTP MCP and Partners MCP adapters. Chat retains explicit
confirmation; tasks retain delegated permissions, execution leases and attempt fences.
The shared worker executes real model turns instead of printing a prompt. Enable it
explicitly with a scoped Agent credential and an explicit Partners tenant/project.

Sandbox resources are bound persistently to the TW owner, conversation or run and
attempt. Models use logical operation handles; the server determines provider resource
IDs. Durable cancellation, cleanup retries, quotas and cleanup-debt inspection operate
only on recorded TW-owned resources. TTL is a fallback. Interrupted model dispatches
recover to review without replaying uncertain external effects. Shell execution requires
an explicitly network-enabled task policy because the provider cannot enforce a
per-command network-disabled policy.

The runtime enforces model rounds, tool-call, context, cumulative token and lease
limits. It validates MCP arguments before dispatch, preserves uncertain-call failures,
and reports actual usage. Dynamic model MCP calls accept JSON-encoded input; existing
approved object inputs remain compatible.

## Durable external events

Business writes persist outbound events transactionally. Delivery uses stable event
identities, leased attempts, bounded retries, timestamped HMAC signatures and observable
history. Replay creates a new delivery under current authorization. Configuration
changes retain authorized metadata and attempt history while invalidating old dispatch
and replay eligibility. Receivers must deduplicate deliveries and verify signatures.

Inbound sources verify signed request bodies before parsing, persist deduplicated
receipts, and apply bounded declarative actions within a fixed project and requirement.
Actions include tasks, comments, permitted task updates, evidence and existing schedule
triggers. Credential revocation and source-generation changes stop stale work. No
plugin ecosystem or separate MCP polling system is introduced.

Actual-model acceptance covers chat, manual and scheduled execution, platform skills,
memories, HTTP MCP and remote sandbox file/command work. Remote cancellation,
application restart without tool replay, live permission revocation, ownership isolation
and deletion were verified. Signed inbound-to-schedule-to-model-to-outbound delivery,
503 retry and replay were exercised in the deployed candidate. Deterministic database
fault injection separately covers lost responses, rollback and retry recovery. Vendor
native clients and OAuth-only interfaces remain outside this acceptance scope.
