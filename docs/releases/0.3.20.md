# Task Weaver 0.3.20

[简体中文](0.3.20.zh-CN.md).

## Reconcile a changed delivery head

Human PR reconciliation can explicitly confirm an inspected provider head with
`tw req repo sync-pr --expected-head`. The server rereads the trusted provider and
retains exact PR, branch, revision, timestamp, authorization and lease checks.
Changed heads require pending workflow stages and no active or approved review.
Observed external merges do not fabricate acceptance or advance workflow stages.
The old and confirmed heads remain in the audit record. See the
[reconciliation guide](../manual-pr-reconciliation.md).

## Bounded Docker readiness inspection

Hosted MCP failures retain internal diagnostic causes while public errors remain
sanitized. Engine capability and image-volume inspection use five-second bounded
administrative deadlines and a minimal engine capability response. This addresses
the reproduced failure where Docker inspection exceeded the previous 1.5-second
limit before MCP initialization began. There are no implicit retries or weakened
Linux, memory, CPU, process-limit, volume, cancellation or cleanup controls.

## Upgrade and verification

There are no new database migrations beyond 0.3.19. Existing public versions and
signatures remain immutable. Back up retained data and follow the
[upgrade guide](../ce-upgrades.md). BusyBox CVE-2025-60876 package-version matches
remain disclosed. Existing reviewed binary replacement and wget control-character
checks are retained; those checks do not establish elimination of the full
vulnerability or distribution approval. No scan suppression is added.

Validation includes pending-head reconciliation and real PostgreSQL authorization
regressions, deterministic slow/unresponsive Docker inspection checks and the
existing full isolated MCP suite. Production browser acceptance remains separate.
