# Ti 执行与 Partners 接入

[English](agent-runtime.md).

建议使用 **Partners Streamable HTTP MCP 作为 Ti 的沙箱接口**。Task Weaver
负责模型请求、工具选择、平台权限、任务状态和 schedule 调度；Partners 负责工作区、
隔离命令、文件和命令作业的恢复。

当前聊天助手已有受限模型/工具循环，能发现和读取 skills、memories、MCP，并按账号确认
设置执行操作。后台任务 worker 是另一条路径：它向 Gateway REST 提交打印任务提示词的
命令，有租约和作业状态管理，但没有真实模型循环。仅注册 MCP 不会让它自动成为 Agent。
本评估尚未实现 MCP 替换或后台模型循环。

评估依据是 Partners v0.1.4，源码提交
`de0290514d87604bdb66bbfa22d89323c59b4a35`，提供七个工具：

| 工具 | 用途 |
| --- | --- |
| `session_create` | 为运行创建受权沙箱工作区 |
| `session_get` | 检查工作区状态 |
| `session_delete` | 清理空闲工作区 |
| `bash_exec` | 提交有期限的异步命令 |
| `job_get` | 查询状态、按游标读取输出 |
| `job_cancel` | 显式取消已接受的命令 |
| `file_ops` | 列出/读取文件、带哈希条件写入文本 |

已从部署中的 TW API 使用现有服务凭据通过官方 SDK 完成握手和七项工具发现。
这只证明协议连接与发现兼容，不能代替真实执行、取消和租户隔离验收。

建议保留一个很薄的 MCP 执行适配器，管理工作区/作业归属、请求 ID、输出分页、查询和
取消；不再继续扩写平行的定制 REST 执行客户端。已有 MCP SDK 连接设施可以复用，但
平台仍须维护运行级别的权限和状态，不能把宽权限服务凭据直接注册为所有人可调用的工具。
模型不能选择基础设施地址、凭据、租户归属或其他运行的资源 ID。

Ti 的真实循环在 TW 内运行：请求模型、校验并执行工具、将结果返回模型，再决定下一步。
平台动作复用受权业务服务；skills、memories 复用作用域服务；外部 MCP 复用注册目录和
策略代理。后台任务还需适配有界委托身份，不能直接复用只面向人类身份的聊天适配层。
schedule 走相同的运行路径，无需独立实现 MCP 变化检测调度器。

聊天与任务共用模型/工具循环、上下文、用量记录和沙箱适配器，但保留各自的执行策略：
聊天沿用当前用户权限、操作确认和流式响应，沙箱按会话归属并采用明确的有限保留策略；
后台任务使用有界委托、持久化尝试和租约，结束后及时回收该次尝试的沙箱；
schedule 启动同一任务运行时，不再维护另一套执行或沙箱生命周期。

Partners 有 `session_delete`。它查询资源真实归属，并校验 `sessions:delete` 及 token 的
tenant/project 范围，但不区分同一范围内的 TW 用户、会话或任务。因此宽权限凭据在知道
其他沙箱 ID 时可能操作它。TW 必须持久化自己的归属映射，在服务端确定 session/job ID，
不能把模型参数、资源名称或同项目关系当成所有权证明；基础设施凭据也应独立且收窄权限。

评估版本默认空闲 30 分钟回收、最长存活 8 小时、每 5 秒扫描一次。网络或 provider 故障
可能延迟删除，不能只依赖这层兜底。当前 TW REST 适配器会在 `finally` 尝试删除，失败只记
日志，尚无持久化清理和重启对账。新接入必须保存清理意图、限制重试、确认真实删除，
提供配额与自身资源恢复机制。聊天可按明确策略短期保留；任务结束应及时回收；
不能通过删除其他工作负载来释放配额。

必须保留这些语义：

- 持久化运行、尝试、工作区、作业和逻辑操作请求 ID。命令成功不代表任务验收成功。
- 限制模型轮数、工具次数、总时长、token 与输出；模型和 Partners 凭据不进入提示词或沙箱。
- 每次操作重新检查租约和权限。后台执行有独立政策，不能绕过聊天确认设置。
- 断开 MCP 请求不等于取消命令；需要显式 `job_cancel` 并确认最终结果。
- 对协议支持的重试保留相同 `requestId` 和参数；评估版本去重窗口为 24 小时。
  不确定执行或创建结果必须对账，不能换新 ID 重跑。
- 完整消费输出游标并保留截断和失败信息。二进制制品下载目前仍走受鉴权 artifact REST。
- MCP 创建的工作区继续通过 MCP 修改，不与旧 REST 写接口混用。
- 评估版本的 CubeSandbox 取消/超时会销毁工作区；后续尝试需创建新工作区，
  并处理已经发生的平台或外部副作用。

交付验收需实际跑通手动任务与 schedule 任务：真实模型、skill 加载、memory 读取、
HTTP MCP 查询、沙箱文件/命令、结果回写及命令失败；还需覆盖取消、撤权、重启和提交响应
丢失，证明不会重复执行或访问其他运行的工作区。通过前保留旧 REST 兼容路径，
并明确其不具备自主模型执行能力。
